# مشروع DevOps Error Lab

مشروع Node صغير، مع 16 حالة خطأ مصطنعة. يحتاج Docker Desktop وGit Bash؛ لا يحتاج Python أو Node على Windows.

## البداية
فك ZIP وافتح Git Bash داخل error-lab ثم:
```bash
bash lab.sh baseline
bash lab.sh list
bash lab.sh run 01
```
الأمر run يفعّل حالة واحدة ويشغّل الأمر الذي يفشل فعلًا. رمز خروج غير صفري متوقع. النتائج داخل results/. يبقى الخطأ مفعلًا بعد التشغيل.
```bash
bash lab.sh run 06
bash lab.sh reset
```
كل حالة تبدأ من النسخة السليمة؛ الأخطاء لا تتراكم. apply/reset يستبدلان ملفات المشروع التجريبي المعروفة، فلا تستخدم السكربت داخل مشروع آخر.

## رفع المشروع إلى GitHub
أنشئ مستودع اختبار فارغًا، ثم من داخل error-lab:
```bash
git init
git branch -M main
git add .
git commit -m "lab: healthy baseline"
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_TEST_REPO.git
git push -u origin main
```
أضف المستودع في منصتنا وشغّل baseline أولًا. بعد نجاحه:
```bash
bash lab.sh publish 01
```
هذا يفعّل الخطأ، يعمل commit، ويرفعه للفرع الحالي. أنشئ New Run في المنصة لنفس commit وانتظر إجابة الطرفين ثم راجع. بعد ذلك فقط:
```bash
bash lab.sh publish 02
```
تابع حتى 16، مع تشغيل ومراجعة كل commit على حدة. لا يكفي رفع جميع commits ثم تشغيل HEAD فقط. publish لا يستدعي API المنصة ولا يراجع الإجابات تلقائيًا.

الحالة 01 تتطلب npm ci؛ قد تمنعها منصتنا مسبقًا باختيار npm install وهذا تصرف صحيح. الحالة 02 تتطلب npm install؛ npm ci قد يكشف عدم تطابق lockfile أولًا. استخدم الأمر المسجل في السيناريو عند اختبار السبب المقصود. الحالات 10 و11 و16 تتطلب مرحلة Docker Build. الأخطاء التنفيذية قد تصلحها المنصة تلقائيًا، لذلك احتفظ بأدلة أول محاولة.

## تشغيل جميع الأخطاء محليًا
```bash
bash lab.sh all
```
هذا لا يرفع commits ولا يرسل نتائج للمنصة. تُسجّل السجلات ورموز الخروج ثم تعاد النسخة السليمة. راجع السجلات لأن تعطل Docker أو سحب الصورة قد ينتج فشلًا لا علاقة له بالسيناريو.

## التقييم
المرجع المتوقع موجود في lab/scenarios.json، منفصل عن سجلات التنفيذ. تصنيف مرجعي مقترح وليس حكمًا آليًا: راجع سجل الخطأ الحقيقي. لا ترسل المرجع للمصنف ضمن مدخلات التقييم. الحالات مصطنعة ومترابطة، وتُعرض كـ Exploratory لا اختبار مستقل. بعض حدود التصنيفات مثل module-not-found تعتمد تعريف taxonomy لديكم.

الأمثلة لا تحاكي انقطاع شبكة أو فشل نشر حقيقي. تغيير registry أو deployment قد يؤثر على موارد خارج المشروع، لذلك لم يُضمّن هنا.
